# ADR-0001: AI は詳細設計・実装、人間はI/Fとアーキテクチャを設計する

**ステータス:** Draft | **日付:** 2026-09-26

### 問い
AIが実装する前提で、設計タスクにおけるAI と人間の役割分担をどのように決めるか？

### 検討した選択肢
- **A: AIが一括して設計する。人間は設計せず、動作の要件適合性のみを確認する** — 最終的にはこれが実現できるアーキテクチャにしたい。ただ、それを実現するためには人間がアーキテクチャ設計に関わる必要があると想像した。つまり①が実現されない。また、異常系の性質上、数時間単位での動作確認が求められる様な動作を考慮する必要があり、その保証は人間が行う必要がある（AIがタイムアウトしてしまうから）。
- **B: AIは各コンポーネント内部の設計を行う。人間はコンポーネント境界の interface を設計する** — 想定するコンポーネント境界は ESP32 と PC だが、企業内のユースケースが必ずしもこのようなアーキテクチャになるわけではないため、ESP32 内部の設計もある程度みておく方が良いだろう。よって、③が不十分。また、ESP32 単体の 設計をすべて AI に任せたとして、AI が①を満たせない。また、②についても、ビジネスロジック（主に制御アルゴリズム本体）がインフラストラクチャ層と独立する様なアーキテクチャにしたい。AIに任せた場合に②を満たす構造が選ばれる保証がない
- **C: AIは各コンポーネント内部の詳細設計を行う。人間はコンポーネント境界の interface と、コンポーネント内部のアーキテクチャを設計する** — 採用
- **D: AIは実装を一切せず、テストコードとソースコードの実装に特化する。人間がすべての設計活動を行う。** ー ③の観点では理想的。ただし、人間の手間が大きいので、開発の持続可能性に乏しい。

### 決定と決め手
以下を判断軸として、最もマシなものを消去法的に選択した。
① AIの担当範囲が、AIの観測ライフサイクルの範疇に収まり、自律的に、設計から、誤りの検出、修正までできるか

* 単一のテストケースが10分以内で完了する。数時間かかるような確認は人間が実施する。
* 以下のテストの範囲で検出できること
  * integration test
  * unit test
* 実機なしにテスト可能であること

② 設計の見直しが必要な時に、手戻りの波及範囲が限定的か

* 別のデバイスの設計に波及しない ← これは要求する
* 単一デバイスの異なるレイヤに波及しない ← これは要求する
* 単一デバイスの同じレイヤの別クラスに波及しない ← ここまでは要求しない。

③ 実装者が、組み込みソフトウェア開発におけるアーキテクチャ設計法を習得できるか

### 影響

デバイスレベルの設計活動が人間に律速するため、開発スピードが落ちる

### 前提

①は、AIの観測範囲外の誤りを人間が確実に検出できることを含意しない。人間はベストエフォートで検出するし、できるだけAIが観測できない誤りが生じない設計を心がける
③は、組み込み側アーキテクチャの設計が落ち着くまで。ADRが5本以上蓄積し、新規の構造的判断が発生しなくなった時。
